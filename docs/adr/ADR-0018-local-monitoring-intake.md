# ADR-0018 — Zabbix intake and durable Border Control

Status: Implemented local defaults, pending deployment/security/native acceptance review — 2026-11-27. Owner authorises LH-103 implementation under ADR-0017. This ADR grants no deployment, scope-upgrade, URL, credential or migration execution authority. Mechanism/default values below are engineering choices, not owner-approved production constraints.

Use existing MonitoringAdapter with strict Zabbix v1 normalization and application-owned intake/processing. Public v2 webtrigger uses static allowlisted HTTP outcomes, preserving the documented Runs on Atlassian eligibility condition; generated correlation IDs are available only in authorised receipts/observations/logs. Do not switch to dynamic response to expose IDs without reviewing eligibility/egress/version implications. No actual eligibility certification is claimed.

Authenticate opaque key ID plus bearer through installed @forge/kvs2.1.3 getSecret; check secret metadata and SQL reference against runtime installation/ISP/source/key/active pointers. Source configuration is server-authorised by stored Atlassian membership; migration also requires Jira admin. Never derive tenant authority from event body, query string or caller-selected source. Verify before JSON parsing/trusted event storage. Static responses contain no payload/token/receipt information. Monitoring-specific log fields are allowlisted outcomes only.

Defaults: POST JSON,64KiB UTF-8,43–128-character base64url random secret (operator generates at least32 random bytes), request age5minutes/future skew1minute, original event age7days/future skew1minute,60 authenticated admissions/source/UTC minute. The exact8-field payload preserves problem linkage and occurrence time. Durable uniqueness tenant/source/external event/kind plus normalized-content fingerprint detects replay/conflict. Bare bearer compromise permits source forgery until disable; timestamps are not signatures, and no HMAC claim is made.

Persist SQL inbox before queue dispatch/acceptance; claims/tokens/one-minute leases and five dispatch/processing attempts bound work and fence old workers. Queue consumer timeout55seconds stays below lease duration. Consumer delivery retry count is capped5; durable interrupted work is exposed to explicit admin recovery (20 rows), not scheduled scanning. Unknown/inactive mappings, source disable and exhaustion retain manual-triage receipts/original time. Recovery evidence never closes a JSM incident. HTTP202 does not prove processing completion.

SQL credential reference intents precede KVS writes; source pointer activation is last. Failed intermediate references cannot authenticate. Rotation uses source CAS and at most24-hour previous-key grace; another rotation during active grace conflicts. Disable precedes cleanup, immediately denying all source credentials even if KVS deletion fails. Bounded cleanup removes only inactive references/secrets; orphan/obsolete references age at least one hour, beyond the configuration handler deadline, to avoid racing live activation. No TTL is trusted for authorisation; previous-key expiry is checked against server UTC on every request. Source/receipt pagination is keyset; recent safe authenticated outcomes are bounded20 per read. No body/title/secret is stored in rejection observations or logs. Retention/distribution policy remains a release review requirement; this development session is bounded, not a production retention claim.

Additive six-table v002 readiness/source/credential/mapping/inbox/observation registry never alters immutable v001 or inventory-ready-v1. Dedicated serial consumer verifies trusted installation and prior readiness; per-DDL checkpoints plus idempotent CREATE permit safe retry. SDK's process-global v001 runner is not mutated. Schema and secret lifecycle partial-failure tests are local simulations; native semantics remain mandatory evidence.

KVS requires storage:app; no egress/remotes/CSP expansion. Latest official registry metadata2.1.3, deduplicated API8.5.1, supported secret methods/type checking/local tests verified. Full Forge lint remains inaccessible after credential-store restriction and external platform timeout; official local manifest schema validation passes. New attack surface/dependency risk requires separate DEVELOPMENT-only approval; prior development exceptions do not transfer automatically.
