# ADR-0021 — Native transition intents and uncertainty

Date:2026-11-28. Status: proposed local implementation defaults; native enforcement and release acceptance outstanding. ADR-0015 server-authoritative guarded closure remains owner-approved. This ADR grants no deployment, permission, workflow or hosted mutation authority.

A future native writer must pass a trusted current actor/tenant/incident/facts/gate/mapping/enforcement review before creating an immutable intent. Intent identity is installation, tenant, incident, operation and expected aggregate version. Persist the plan, originating account and enforcement review before any HTTP side effect. Only a prepared zero-attempt intent may claim a send lease. Expired sends and uncertain responses reconcile the same intent without another POST. Three read reconciliations and one POST are bounded proposed defaults; exhaustion enters manual review rather than silent retry.

Additive local v006 defines a separate schema readiness registry and transition-intent table, preserving all v001–v005 definitions. The SQL adapter uses single-statement CAS and scoped parent/actor predicates, live tokens/time/version fencing and bounded structured audit. Readiness depends on the prior registries. Neither DDL nor repository is registered in a deployed runtime or migration queue by this milestone. Local adapted SQLite concurrency checks do not establish Forge/TiDB native semantics.

The resolver-bound asUser gateway verifies the actual account, linked project/issue, eligible transition, exact from/to status and supported required fields. An accepted HTTP response or observed target status does not prove the exact historical actor, transition time or atomic consumption of Light House guards. Observations retain server read time and postcondition-only causality. No conversion to native confirmation exists. Closure remains disabled until a concrete reviewed preflight/evidence provider, native bypass enforcement and confirmation provenance are accepted.

An independent read-only owner terminal discovery tool can enumerate accessible service desks/request types/required field metadata using existing authorised credentials. It is development tooling, never application authentication or a new Forge permission. It makes only fixed bounded GETs and returns sanitised projections; credential visibility does not prove Forge app permissions or native write acceptance.

Alternatives rejected: blind POST after timeout, equating a status read with a caused transition, bypassing native conditions, using Preview validators without review, and exposing arbitrary diagnostic/SQL endpoints. Standard workflow-condition/read-only-field primitives remain an investigated candidate with unproven atomicity/actor binding. See [native enforcement options](../integrations/native-workflow-enforcement-options.md) and [transition contract](../integrations/jsm-transitions-contract.md) for official references verified2026-11-28. Forge/ADS MCP unavailable.
