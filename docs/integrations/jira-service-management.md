# Jira Service Management integration — planned Sprint 4

Create real requests via `POST /rest/servicedeskapi/request` with configured serviceDeskId, requestTypeId and required requestFieldValues. Jira platform `POST /rest/api/3/issue` is an alternative issue mechanism, but ordinary issue creation alone does not prove a customer request/portal lifecycle is configured. Prefer the JSM request endpoint and verify its permissions, fields and request-type association on the target site. Backend app context and Jira project permissions must both allow the operation.

Proposed incident content: synthetic site/uplink/carrier aliases, source problem reference, aggregate known/unknown impact, priority, team/assignee mapping, policy version, operational warning/deadline, incident ID and stable reconciliation marker. Avoid customer lists, contacts, raw payloads, credentials and unnecessary topology details. Validate Jira field metadata instead of assuming IDs/names or that generic due date fields support timestamps. Verify assignee accountId is active/assignable and use manual assignment when mapping fails.

Persist intent before creation and reconcile unknown results using the marker included in the initial request; see event lifecycle for search lag/manual-review rules. Map returned issue ID/key once. Rate limiting follows Retry-After and bounded retries; validation/permission failures surface as actionable configuration errors. Resolution uses configured workflow transitions and confirmed timestamps, not guessed transition IDs. Manual changes/reopen require reconciliation.

JSM owns native SLA calendars/goals and notifications; read native metrics through GET request SLA endpoints. App operational datetime fields remain separate. Configure native notification recipients/public versus internal comment behaviour and automation for app warning/breach field updates, then verify delivery with synthetic users. A REST response alone cannot prove mail delivery.

Official sources, verified 2026-11-24: [JSM REST](https://developer.atlassian.com/cloud/jira/service-desk/rest/), [request operations](https://developer.atlassian.com/cloud/jira/service-desk/rest/api-group-request/), [Jira REST](https://developer.atlassian.com/cloud/jira/platform/rest/v3/), [notification setup](https://support.atlassian.com/jira-service-management-cloud/docs/set-up-notifications-for-your-customers-and-team/). No requests, fields, rules or notifications have been configured.
