Client commands cannot supply account, transition/status IDs, mapping, gate, facts revision, enforcement evidence or fields. Trusted preflight binds installation/tenant/account, current operation/version/facts/gate, durable linked issue/project, admin-reviewed mapping version, from/target status and optional resolution ID. It must verify current actor/team/authority and native enforcement evidence; missing proof fails NOT_READY. A caller-set boolean is not evidence.

EnforcementEvidence is a server-owned review reference scoped to installation/tenant/project with verification/expiry UTC. This component supplies no production evidence provider. Mock tests inject synthetic references only; their presence proves no native enforcement. The future preflight adapter must read real approved evidence and use fixed TransitionError contracts for denial/unavailability.

- Atomic expected-version/live-lease claim before HTTP. Only prepared/attempts0 may enter sending. Expired sending, reconciling or ambiguous may only reconcile, never send. ## HTTP and reconciliation behavior

The asUser gateway checks actual account, exact issue/project/from status and a unique available mapped transition/target. It never sets skipRemoteOnlyCondition or includeUnavailableTransitions. Unknown/missing/duplicate metadata, wrong actor/project/status, unsupported required fields or unverified resolution values prevent sending. Bodies contain only transition ID and optional resolution ID; no customer/monitoring payload, private URL or credential material.

204 is classified accepted-response, not an invented timestamp.401/403 map to PERMISSION, selected definite configuration4xx to CONFIGURATION,429 to RATE_LIMITED. These rejections end in manual review; **no automatic second POST**, even for429, is introduced in this conservative slice. Unknown statuses, network errors or response/settlement loss remain ambiguous. No raw error body is read/exported or logged. Unexpected exceptions become fixed UNAVAILABLE.

After accepted/ambiguous POST, or during later bounded reconciliation, GET issue reads exact issue/project/status. A matching target yields an observation with **server read time** and causality **postcondition-only**. Another user or process may have moved the issue, or a late response may have been lost. Therefore this result cannot prove an exact transition's actor/time/causality and cannot populate OperationRepository.NativeConfirmation.confirmedAt. Even observation with a known204 response is not a verified historical transition timestamp.

Every TransitionResult has nativeConfirmationAvailable:false. NativeClosureAvailable and the existing nativeConfirmation reader must remain fail-closed until an independently reviewed writer/reader plus bypass-enforcement evidence provides the required actual confirmation. The component deliberately exports no conversion from observation to NativeConfirmation. No matching status or temporal candidate is silently upgraded to causal proof.

A live lease blocks concurrent work. A success arriving after lease expiry fails settlement and later reconciles the same immutable intent without another POST. A failed settlement leaves durable uncertainty; arbitrary SQL exception text is not exposed. Three unsuccessful reconciliation claims terminate in manual review. Review expiry or binding/mapping changes require manual review rather than rewriting a prior ambiguous intent.
