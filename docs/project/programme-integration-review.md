## Reviewed controls

- Runtime derives installation from `getAppContext`, restricts to DEVELOPMENT, projects unknown input fields and resolves the Atlassian actor server-side. Overview uses tenant read permission; process/publish/configure/create/schema actions require current configure membership. Migration and JSM configuration additionally require Jira global admin. Caller-supplied installation/tenant inside JSM configuration is rejected and replaced by trusted context.
- Monitoring worker verifies installation, tenant/inbox UUIDs and fixed payload keys. Mapped receipt lookup joins the stored active source binding. Incident evidence is projected to NormalisedMonitoringEvent fields, so adapter-only title data cannot poison exact evidence equality. Durable evidence precedes enrichment, supports recovery-before-problem and does not itself change operational state or SLA.
- Incident uniqueness is installation/tenant/source/problem; duplicates return the immutable winner. SQL inventory identifiers come from a closed registry; record values and parameters remain tenant-scoped. Completeness limit1000 fails closed rather than using a truncated impact snapshot. Unknown failover is retained as uncertainty. Domain impact and policy logic validate scoped references and source UTC; SLA snapshot selection does not use delivery time.
- Operational policy writes have tier/tenant CAS and current final parent guards. Publication histories must retain immutable prior snapshots and deterministic effective boundaries. The exposed cross-tier identity path above is corrected through server-owned UUID generation; new open-ended policy replacement also needs a deliberate effective-boundary procedure before full policy administration acceptance.
- JSM configuration requires server-bound IDs, four distinct customfield IDs, priority identifiers and fresh gateway metadata verification. The asApp gateway uses fixed supported Jira/JSM paths with route parameters. Search builds JQL only from constrained numeric project/field IDs and generated marker, checks exact marker, project, service desk, request type and unique result identity before linking. Application secrets and private URLs are absent from JSM requests.
- SQL JSM intent uniqueness is installation/tenant/incident; configuration/request snapshots are immutable. Claim increments attempt/version and acquires a bounded live lease before HTTP. Settle atomically saves state, unique installation/issue mapping and bounded audit in one row/token/version/lease CAS. No multi-statement transaction is assumed. A conflicting cross-tenant issue mapping fails the entire UPDATE without partially linking the row.
- Expired sending/reconciling work can only reconcile. Missing, failed, zero-result or ambiguous search never proves the earlier POST failed and never authorises another POST. Rate-limited create retries are bounded and due-time guarded. Native issue creation uncertainty stays manual/ambiguous after bounded reconciliation rather than duplicating requests.
- Error/log output is fixed-code and allowlisted; raw Jira errors, payloads, credential material and arbitrary exceptions are not passed to logs/UI. Structured log fields remain within the existing logger boundary. Runtime-generated correlations and durable receipt evidence remain distinct; temporal attribution alone is not exact correlation proof.
